# Luna Bot · Minis 风格 Android 客户端

> **Luna Bot** 是独立分支：安装包名改为 `com.dexbot.companion`，可以和原版同时安装、对照使用；桌面端应用 ID 为 `com.dexbot.app`。
>
> 基于 [Luna Bot](https://github.com/milind-soni/OpenMausBot) 官方 **android-release/v1.5.0** 伴侣客户端，以及社区全量简体中文汉化 [soyeoning94/Luna Bot-Android-CN](https://github.com/soyeoning94/OpenMausBot-Android-CN)，按 **OpenMinis** 的移动端体验重做界面，并接入自建 **Luna Bot Cloud**（`https://cloud.dexai.vip`）。
>
> 保留上游 Apache-2.0 许可与署名。手机连的是电脑上的 companion；局域网直连、Tailscale 和自建配对服务都保留。

## 为什么做这个

官方 Android 客户端功能完整，但界面全是硬编码英文，交互是 Telegram 式；社区汉化只翻译了文案，没有改交互。对中国用户来说，问题不是"能不能用"，而是"不像自己每天在用的手机应用"。

这次改造的原则：

1. **先像微信/日常 App 一样顺手**：底部只有一条安静的操作栏，一个暖色 FAB；列表是"标题 + 摘要 + 时间 + 未读点"。
2. **再像 Minis 一样克制**：黑白为主、分组卡片、少用彩色；Bot 的回答直接排在页面上，不套气泡；你的话才是右侧灰色气泡。
3. **中文优先**：24 小时制、今天/昨天/星期、配对/设置/错误提示全中文；国产 ROM 的保活设置直接给到系统页面。

## 改了什么

### 设计系统
- 新增 `MinisDesign.kt`：Minis 风格的配色、圆角、分组卡片、分隔线、FAB。
- `CompanionTheme` 从"绿色 Material"切换为"黑白 + 一个蓝色强调 + 暖米色 FAB"。
- 头部图标、返回键改为纯图标（无灰色圆底），和 Minis 一样把注意力留给内容。

### 会话列表
- 居中标题 + 电脑名/连接状态；右上角设置。
- Bot 行改为 Minis 式：44dp 头像、标题、摘要、时间、蓝色未读点；去掉右侧箭头。
- 状态直接写成"正在工作 / 等待你处理"，不再用大色块胶囊。
- 底部操作栏：安静的状态胶囊 + 搜索 + 暖米色新建 FAB；"新建分区"移出主界面。
- 时间/日期中文化并固定 24 小时制（`03:35`、`昨天`、`星期一`、`11月10日`）。

### 聊天
- Bot 回答 **不再套气泡**，直接铺在页面上，保留 Markdown、引用、代码块。
- 用户消息为右侧灰色气泡（浅色 `#F2F2F7` / 深色 `#2F3A5C`），无尾巴。
- 工具步骤默认折叠成一行："已运行 5 个步骤 · 展开"，失败步骤仍然显示。
- 输入区改为白底细边框胶囊；`+`、语音、发送都在一条栏里；发送键黑底白箭头。
- 审批卡：标题 + 说明 + **纵向全宽按钮**（主操作黑色、拒绝浅色），"始终允许"收在下面，避免误触。

### 设置
- 全部分组为 Minis 式灰色圆角卡片。
- 新增 **「国产手机保活」**：一键打开电池优化白名单、应用详情（自启动/后台管理）、通知设置，并附一加/OPPO/realme、小米、华为的具体路径。
- 活动详情默认改为「精简」。

### 配对 / 引导
- 配对卡片改为分组卡片；确认电脑、输入配对码的层级更清楚。
- 配对的英文提示全部翻译成中文。
- 引导页主图标从淡紫色圆改为黑白圆角方块，标题加粗放大。

## 真机上的第二轮优化（一加 15T）

装机后发现三处真机问题，已经修掉：

1. **输入框被挤爆**：在 360dp 宽的手机上，原来"外置 + 按钮 + 内置换行斜杠按钮"占掉了太多宽度，
   `向 Luna Bot 提问` 被挤成两行。现在把 `+` 收进输入胶囊（Minis 的做法），去掉多余的斜杠按钮
   （输入 `/` 仍会自动打开命令面板），占位文字单行显示。
2. **Bot 没有"表情"**：聊天页头部现在直接使用桌面版的 SupaMaus，并跟随
   `MausState` 变化——思考、工作、未读、完成时表情不同；`思考中… N 步` 卡片和
   消息流底部的等待行也用同一张脸。主 bot（`chrome` 色）用的是桌面 App 图标里
   那条银色渐变（`mascot-grey`：白 → #E6E8EB → #B7BBC2 → #848A94 → #5B616B），
   不是灰色平涂；名字后面补了桌面版的蓝色小皇冠。
3. **不要动画**：去掉了消息流底部的三点循环动画；顶部 bot 头像、思考卡、列表头像
   都改成静态表情——状态会变，但不会一直眨眼/呼吸/循环播放。
4. **电话图标太丑**：改为 Material 的 `Phone` 图标；`ic_display` 保留为电脑屏幕入口。
5. **空群组区块太占地方**：没有群组时不再画 64dp 虚线大圆，改成列表里一行安静的
   `＋ 新建群组`。
6. **头部副标题**：主 bot 的主线程现在显示「总协调机器人」，不再显示线程名「你好」；
   任务线程才显示任务标题。
7. **快捷指令条**：右侧加了一层渐隐，最右边的「下一步」不会再被屏幕边缘硬切。
8. **底部状态胶囊**：没有动态时压成一行「一切平静」，不再占两行。
9. **模型提供商中文化**：OpenCode / OpenAI / Claude / DeepSeek / 通义千问 / Kimi 等
   常见 instance 在模型选择器里显示中文名；用户自定义的「词元交易市场」等名字保留。
10. **Markdown 表格**：新增 GFM 表格解析（`| 表头 |` + `|---|` + 行），聊天里直接渲染成
    可横向滚动的表格，不再把整张表压成一行 `|` 乱码。`core` 里补了三个表格单测，
    `./gradlew :core:test --tests "com.openmausbot.companion.core.MarkdownTest"` 通过。
11. **系统栏同色**：Minis 那种“全黑”不是把状态栏涂黑，而是 edge-to-edge：状态栏/手势栏透明、
    关闭 Android 15+ 的 contrast scrim、窗口底色跟随页面（深色纯黑 / 浅色纯白），系统图标明暗
    跟随主题。现在顶部和底部不再露出 `#1C1C1E` 的灰边。
12. **聊天内搜索**：聊天页右上角新增搜索入口，全屏搜索已加载的消息；命中的关键词高亮，
    点结果直接跳回原消息。真机/模拟器已验证搜索与跳转。

## 第三轮：动效与交互

这一轮补的是"手机聊天该有的手感"。所有动效都是一次性反馈，不做常驻循环——Bot 空闲时依然完全静止。

1. **页面转场**：列表 → 聊天 → 设置按方向滑入滑出，返回时反向；任务切换只做淡入淡出，
   因为那是原地换地址，不是翻页。
2. **阅读位置不再被抢**：以前 Bot 一吐字就把列表拽到底部。现在只有你在底部时才跟随；
   往上翻历史后，新消息只让右下角按钮亮一个蓝点。
3. **回到底部按钮**：悬浮圆形按钮，弹簧缩放入场，点击回到最新并带触感反馈。
4. **消息进场动画**：新消息淡入；折叠展开、未读排序变化时，行与行平滑移动而不是跳变。
5. **头部细分割线**：滚动后才淡入，静止时头部就是页面的一部分。
6. **Bot 表情反应**：表情状态变化时头像做一次短促回弹，随后完全静止——有反应，但不乱动。
7. **全局按压回弹**：FAB、发送键、返回键、搜索等所有圆形控件按下缩小、松手弹回。
8. **听写波形**：录音时麦克风按钮变成四根跳动的红条，只在实际采集时出现。
9. **动态标题过渡**：底部动态胶囊的标题变化时上滚淡入；连接状态横幅出现/消失时展开收起。
10. **长按 FAB = 新建分组**：Minis 化后"新建分区"入口从底栏消失，现在挂在同一个暖色按钮的长按上。
11. **引用回复**（新功能）：长按任意消息 → 引用回复，自动把前 4 行以 Markdown 引用插入输入框。
12. **修复长按双菜单**：此前长按消息会同时弹出系统选择工具栏和 App 菜单；现在文本选择统一
    收进"选择文本"对话框，长按只做一件事。
13. **恢复聊天定位修复**：进程恢复时等真实历史页加载完再定位到底部，不再停在历史中间。

## 第四轮：语音消息 + 文案收尾

### 按住说话

- `+` → **语音消息** 打开录音面板；按住大按钮说话，松开发送，上滑取消。
- 实时计时（最长 60 秒）、真实振幅波形、录音时红色状态、上滑时按钮变叉、取消提示。
- 录音为 AAC / MP4（`.m4a`），单声道 64 kbps；60 秒约 480 KB，远低于 25 MB 附件上限。
- 权限走现有的麦克风授权通道；拒绝后可原地重新授权。
- 松手后直接发送，不需要再点一次发送键。发送失败会在输入区给出中文错误。
- 服务端本来就接受 `audio/mp4` 等 10 种音频 MIME，桌面端的附件画廊用 `<audio>` 播放；
  这次只是把手机端过窄的附件策略和对 `attached-file` 的解析补齐。
- 自己发出的语音在手机上也渲染成可播放的语音条，不再是"文件"卡片。

### 文案收尾

- 本地网络发现失败、语音/试听播放失败、例程超时校验、话题文件夹的无障碍描述、
  分享失败提示里的英文句子，全部改为中文。
- 例程页的 `Webhooks` 标题统一为 `Webhook`。

### 测试

- 新增两条单测：`.m4a` 的 `attached-file` 解析为语音条；`audio/mp4` 通过附件策略。

## 第五轮：电脑画面为什么是黑屏

查下来的结论：**功能没坏，是这一轮机器人没有使用图形电脑**。电脑端只在一个回合真的操作桌面时才截屏并推送；只在终端里跑命令的回合没有画面。旧界面在这种情况下一直转圈，加上顶部和底部露出白色系统栏，看起来就像坏了。

现在：

- 电脑画面全屏纯黑，状态栏/手势栏与页面同色，系统图标自动反色；离开时恢复。
- 空闲时不再转圈，直接说明「画面只在机器人实际操作电脑时产生」，并提示去电脑端检查该机器人的「电脑」访问。
- 机器人工作中长时间没有画面时，说明「本轮可能没有使用图形电脑」，不再假装马上会有画面。
- 会话里已有历史截屏时，先显示最近一张，角标为「上次画面」。
- 云电脑 / 本地 VM 支持按需截图：机器人空闲时也能拿到当前桌面，状态显示「截图」。
- 「这台 Mac」没有 HTTP 截图通道，只能等机器人使用电脑时的实时画面；这是桌面端能力限制，不是手机端。

## 第六轮：外观、语音入口、模型名

1. **主题设置**：设置 → 外观 → 主题，可选「跟随系统 / 浅色 / 深色」。选择持久化，
   状态栏和手势栏的图标明暗同步切换。
2. **长按麦克风发语音**：输入栏的麦克风单击仍是语音听写，长按直接打开「按住说话」；
   语音入口不再只藏在 `+` 里。
3. **模型名称中文化**：Claude / GPT / DeepSeek / Kimi / GLM / Gemini / Grok 等常见模型
   统一成可读名称；只有原始 id 的条目（如 `kimi-code/k3.1-pro`、`zai-coding-cn/glm-5.3`）
   会去掉厂商前缀并补全为「Kimi K3.1 Pro」「智谱 GLM 5.3」。
4. **深色模式细节**：语音面板的麦克风图标在深色下改为黑色，不再白底白图标。
5. **语音条重做**：播放器不再占满一行。32 dp 播放键使用前景色底 + 页面色图标
   （深色下是白底黑三角，不再是空白圆），进度条改为 3 dp 细线，整块限制在 180–260 dp，
   右侧只显示时长。

## 第七轮：Liquid Gloss 与实用功能

### 视觉

1. **Liquid Gloss 材质**：新增 `minisGloss`（半透明填充 + 0.5 dp 上缘高光 + 镜面渐变），
   搜索胶囊、动态栏、底部状态胶囊、命令 HUD 共用同一材质；没有逐帧抓背景，API 26 与 37 表现一致。
2. **聊天头部玻璃**：消息从标题和头像下面滚过，深色下能看到极淡的透出；标题始终保持在最高对比度。
3. **FAB 镜面**：暖米色按钮加了顶部高光、细亮边和 8 dp 投影，按压缩放时阴影一起收。
4. **输入胶囊玻璃**：从“页面色 + 描边”改为玻璃填充 + 细边，深色下不再是埋在页面里的纯黑块。
5. **弹窗/面板跨窗口模糊**：API 31+ 上由系统模糊背后的界面（底部面板、机器人设置、会话面板），
   26–30 或系统关闭模糊时自动退化为原来的遮罩。
6. **色系统一**：`tertiary` 不再回落到 Material 的紫红；分段控件的淡紫选中态改为黑白；
   CommandHud 五个高饱和色收成一个蓝色导轨；警告橙/成功绿/危险红统一为三个令牌。
7. **精致度**：电脑页返回键改为 48 dp 触控目标（保留 32 dp 视觉）；两个搜索框统一 52 dp / 17 sp；
   分组标题、圆角、页面边距收敛到令牌；删除无调用的 `NamePill`。
8. **语音条圆点修正**：之前 10 dp 的播放位置点贴在滑块槽顶部，看起来浮在进度线上方；
   现在点在自己的槽里垂直居中，实测点中心与 3 dp 轨道中心完全重合。

### 功能

1. **会话内全文搜索**：搜索框现在同时查本地已加载消息和电脑的全文索引（`/api/search`），
   结果去重合并；点较早的命中会按消息 ID 加载上下文并定位，定位时给悬浮头部留出偏移。
2. **例程运行已读/取消**：运行记录展开后可以「标记已读」或「取消运行」，走白名单里的
   `POST /api/routine-runs/{id}/seen|cancel`。
3. **手动压缩上下文**：机器人设置 → 上下文 → 压缩上下文，确认后触发 `/compact`；
   摘要会作为普通消息出现在会话里，历史消息保留。
4. **通知栏直接审批**：审批通知带「允许 / 拒绝」两个动作。Android 的通知不携带卡片内容，
   所以按钮会先拉取该会话最新的待批卡再回答；技能安装卡和结构化问题卡拒绝在通知栏处理，
   会提示回 App 查看。
5. **通知按房间归组**：帧里新增 `groupId`，同一房间的通知在通知栏堆叠，不再散落在不同机器人下。

## 第十轮：错误界面、离线缓存、语音与头像动效

这一轮处理的是"用久了才会遇到"的七件事：

1. **报错不再是原生界面**：Material `AlertDialog`（"出错了" + 确定）和唯一一个系统 `Toast`
   都删了。新的 `InlineNotice` 是应用自己的玻璃提示卡（图标 + 标题 + 正文 + 可选动作），
   `ActionNoticeHost` 把它浮动在所有页面底部，8 秒自动收起；通知栏审批失败在 App 前台时
   也走这张卡，后台则发一条可点的本地通知。
2. **离线有缓存**：`CompanionState` 以前只在内存里，断电重开就是"暂无智能体"。
   现在每次成功 `hydrate` 会把 roster 快照（每个线程最后 10 条消息，JSON）写到
   `filesDir/roster-cache/<connectionId>.json`，冷启动先渲染快照再联网；
   顶部提示卡会写"显示 2 分钟前的名单，正在自动重试"，并带一个「重试」。
   快照按电脑分开、原子写入、超过 2 MB 不写、解除配对时删除，也不进备份。
3. **语音消息能收到了**：机器人发来的语音有两种线形：TTS 生成的 `kind:"audio"`，

   文件名，`kind:"file"` 更是完全没有渲染分支，所以整行是空的。现在两种都收，
   按 mime 或扩展名判断，语音行进播放器、其余文件进文件卡。
4. **App 图标换成 bot 头像**：旧的绿色老鼠换成一个 108 dp 自适应图标：

5. **底部「动态」按钮**：原来的 hub 线稿在 22 dp 缩成一团看不清，换成铃铛；

## 第十二轮：真正的动画（脸引擎）

上一轮的"头像动效"其实是滤镜：一张 512×512 的 PNG 整体缩放 1.8%，再叠一条白条扫过。
眼睛烧在像素里，所以永远不可能眨、不可能看别处。这一轮把脸改成**每帧重画**。

### 先量，再画

用参考截图（`docs/grok-avatar-library.png`）量了 Grok Bot 头像的真实几何，发现我们一直画错：

| 量出来的 | Grok 参考 | 我们原来 | 差值 |
|---|---|---|---|
| 左眼中心 | (-0.323, +0.212) r | (-0.299, +0.132) r | 高了 0.08r |
| 右眼中心 | (+0.323, -0.012) r | (+0.336, -0.086) r | 高了 0.07r |
| 两眼连线 | -19.1° | -19.1° | 一致 |
| 胶囊尺寸 | 0.245d × 0.125d | 0.237d × 0.119d | 基本一致 |

结论：**倾斜对了，整组眼睛偏高**——两眼的连线本来就该是歪的（左眼比右眼低），
但整组应该再往下 0.08 个半径。104dp 的头像上就是 4dp，在截图里一眼能看出来。

### 脸引擎

- `BotFace.kt`：一个圆 + 两只胶囊，用 `Canvas` 每帧绘制。四个通道——眨眼、视线、
  脸部倾斜、呼吸——全部是时间的纯函数。
- `FaceClock.kt`：**全 App 一个** `withFrameNanos` 循环，引用计数，没有脸的时候完全停。
  每张脸用自己的种子从时间推导自己的节奏：两张脸不会同时眨眼。时间在**绘制阶段**读取，
  一帧只重绘、不重组、不重新布局。
- 状态机：空闲（视线在几个点之间扫）、思考/工作（视线上抬、微微眯眼）、
  倾听（睁大、锁定）、久闲（45 秒没人碰，眼皮慢慢垂下去；一碰就醒）。
- 尺寸策略：≥72dp 全通道；列表行只给眨眼和慢视线；24dp 只改视线和眯眼——
  这个尺寸下眨眼只有 2px，看不出来，只会闪。

### 聊天流

- **打字机**：回复按阅读速度揭开（30–60 字/秒，落后太多就加速追），
  不再是服务器推一块就整块跳出来。超过 2000 字不揭示——重解析大段 markdown
  换不来观感。
- **新行入场**：等待行和回复行 180ms 淡入 + 上浮，消息是"进来"的，不是"被重画"的。
- **碎碎念交叉淡入**：第二行文字换了不再硬切，200ms 交叉 + 位移。
- **工作环**：110° 弧从纯色改成 sweep 渐变（头亮尾淡），转起来像在加载，不像仪表盘。
- **回声机**：输入框为空时是麦克风，有内容时同一位置淡入缩放成发送箭头（原来是硬换图标）。

### 资产同步

8 张预设头像 PNG 和启动图标（含 monochrome 的挖洞路径）都按同一套坐标重画了：
PNG 是上传给电脑端、给别的客户端看的，App 里画的脸必须和它长得一样。

  视线在动，中间那一帧是眨眼。`docs/round12-face-blink.png`。
- 工作环两张间隔 0.35 秒的截图里位置不同，渐变头尾可见。
- 启动器上的图标已换成新几何：左眼低、右眼高。
- 新增 `BotFaceRigTest` 7 条：静止脸恒定、同种子同帧、不同种子不同节奏、
  每个周期必有一次闭眼、视线不越界、几何常量对齐参考、情绪改变眼睛但不改节奏。
- 其余 136 条失败仍是既有的英文文案断言，与这一轮无关。

## 第十三轮：多 bot 不再同步、动作变多、指挥官帽子

### 一个真 bug：同一颜色的 bot 会同时眨眼

脸的种子取的是**调色板**（`preset.key`），所以列表里所有黑头像共用一套作息——
看起来整齐，其实是"多 bot 同步动作"。种子改成 **bot id**：同一个颜色不再是同一个
作息，两张黑脸各眨各的。行内测过：连拍 14 帧里只有一行闭眼，其余各行保持打开。

### 静止时不再只有眨眼

空闲脸每 2.2–4 秒做一个小动作，带 260ms 进出缓动：歪头 ±3–4.5°、眯眼到 74%、
睁大 112%、往斜上方瞥一眼、歪头同时往下看。手势只发生在 `IDLE`——工作和倾听时
眼睛已经在表达状态，再加手势会自相矛盾（有测试钉住）。

### 时间条与名字同基线

13sp 的时间原本与 17sp 的名字**居中对齐**，名字有没有下伸部（"Poppy" 的 y）会让时间
上下浮动几像素。改成 `alignByBaseline()`，一列时间落在同一条基线上。

### 指挥官皇冠

主 bot 右下角的星标换成戴在头上的**黑金皇冠**：金帽墙（中间下兜，贴合额头弧线）+ 三个黑尖
带金边和金球 + 三颗深色宝石。它**由脸部的 rig 自己画**（`BotFace.drawCrown`），拿到的是同一份
`FacePose`——所以它跟着呼吸一起缩放、跟着歪头一起旋转。第一版是用 Canvas 单独画的军官帽，
太大、凭空浮在头顶、和脸没有任何联动，看起来像贴在屏幕上的贴纸；第二版退回成矢量图叠在
头像上，问题一样。皇冠必须长在脸上，这一条只有"和眼睛共用同一套变换"能满足。

帽墙的弧线方向也踩过一次坑：弧朝上时像发箍浮在头顶，朝下（中间低、两端高）才像箍在额头上。

星标空出的右下角留给了连接指示灯。

当前版本 **1.6.9**（versionCode 10609）。

1.6.9 是把并行完成的一轮界面改动合进主线后的构建：图标换成线性一套、新建 Bot 改为进编辑页
保存时才创建、主页与聊天收紧间距。皇冠与列表基线也在这一版里。

## 更新渠道（ZCode 网页托管）

固定下载页：**https://mausbot-cn-7i51.zai.site/**

- 页面托管在 ZCode Sites，包含 `index.html`、`update.json` 和一个 arm64 APK。
- App 的 **设置 → 关于 → 检查更新** 会读取 `update.json`，比较 `versionCode`。
  有新版本时下载 APK、校验 SHA-256，然后交给系统安装器。
- 安装器仍会弹出系统确认；普通应用无法静默安装。配对和聊天数据会保留（同包名、同签名）。
- 站点是公开的，但 APK 里没有 API 密钥或配对令牌；密钥保存在 App 的加密存储中。
- `dist` 构建只保留 arm64 原生库，18 MB，符合站点单文件 25 MB 的限制。
  它复用本机 debug 签名，因此只能覆盖安装同一签名构建的旧版本。
  换一台机器构建会换签名，那时需要先卸载一次。
- 设置页同步重做：大标题、52 dp 行高、分组卡片、行间分隔线、右侧状态/箭头，
  「后台连接」改为开关；通知已开启时不再显示一条灰掉的死按钮。

发布新版本：

1. 修改 `android/app/build.gradle.kts` 里的 `appVersionName`（`versionCode` 自动推导）。
2. `./gradlew :app:assembleDebug :app:assembleDist`。
3. 把 `app/build/outputs/apk/dist/app-dist.apk` 复制到 `.zcode-site/stage/dist/`，
   用 `shasum -a 256` 和文件大小更新 `update.json`，同步修改 `index.html` 的版本与更新说明。
4. `node .../zcode-site.mjs deploy .zcode-site/stage`（站点已链接，不需要 `--new`）。
5. 手机：设置 → 关于 → 检查更新 → 下载 → 系统确认安装。

## 已知差距 / 下一步

这次是把"骨架和主路径"做成 Minis 风格的中文客户端，还不是完整产品。按优先级：

1. **模型条目中文化**：提供商名称已经是中文，但模型条目本身仍多用服务端返回的英文 label；
   下一步按 DeepSeek / 通义 / Kimi / GLM / Claude / GPT 给常用模型配中文名。
2. **通知栏快捷审批**：现在点通知进入 App 再审批；可以在通知上直接"允许一次 / 拒绝"。
3. **国产 ROM 深度保活**：已给系统设置入口；还可以针对一加/小米/华为做各自的自启动页直达和引导检测。
4. **分享到 Bot**：系统分享入口已存在，但还没有从微信/浏览器分享后的"选择 Bot 并发送"确认页。
5. **语音转写**：语音消息目前作为音频文件发送；如果电脑端接入了 Whisper 等转写工具，
   可以自动把转写文本一并附上，让 Bot 不依赖音频文件也能理解。
6. **本机桌面截图**：「这台 Mac」目前没有 HTTP 截图接口，机器人空闲时手机看不到桌面；
   需要电脑端补一个截图路由，手机上再接入。
