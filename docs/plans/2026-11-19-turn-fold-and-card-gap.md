# 回合折叠与卡片间距 —— 一页纸

日期：2026-11-19
状态：实施中
相关：`docs/plans/2026-11-19-giant-card.md`（同一屏的问题卡）

## 现象（一张截图里四条）

1. **审批卡被当成 bot 消息。** 卡片和它下面的 bot 回答之间只有 4dp，卡片的左上角
   还贴着上一条气泡的底角——卡片读起来像 bot 自己说的一段话。
2. **`已处理` 和 `已运行` 是同一件事的两个折叠。** 一个回合既有「已处理 1分31秒」，
   又有「已运行 6 个步骤」，两个胶囊、两种图标、两种动词（`显示` / `展开`）。
3. **`已处理` 里折着 bot 的话。** 展开后，bot 的叙述气泡是整宽灰色方块，和外面
   窄胶囊不是一个层级；这正是「矩形阴影与气泡割裂」。
4. **消息滑到底贴着快捷卡片。** 列表底部的留白 10dp，最后一行气泡的底边几乎
   压在快捷回复胶囊上。

## 根因

- `TranscriptLayout.endsRun` 只问**下一条**是不是文本（iOS 的写法，那时 bot 回复是
  页面上的裸文本，没有形状可拼）。手机上每条回复都是有填充的气泡，所以卡片跟着
  气泡时，气泡以为「后面还是文本」，把底角收了进去；卡片自己也把顶角收进气泡。
- `transcriptRows` 把**叙述**折进 `AssistantTurn`，工具步骤另走 `ActivityRun`。
  于是同一回合两个折叠，且 bot 的话默认不可见。
- `BOTTOM_CONTENT_GAP` 写死 10dp，没有算上快捷胶囊的高度感。

## 改动

### 1. `endsRun` / `endsRowRun`：两侧都问

加上「当前这条是不是文本」。卡片、工具胶囊、截图这类行两侧都断开 run，气泡的
四角保持圆角，和卡片之间回到 `TURN_GAP`（16dp）。chip 夹在两段文本之间时，
两段文本也各自独立——中间确实隔着一个看得见的东西。

### 2. 一个回合只折一次，只折步骤

`transcriptRows` 在 `REDUCED` 下把**已完成回合的成功工具步骤**折进
`AssistantTurn`；叙述（bot 的 text）不再进折叠，照常显示。

- 折的门槛与桌面 `toolStepFolds` 一致：只折 `ok == true` 的步骤；失败行、状态行
  （`notice:` / `recovery:` / `stopped:` / `error:`）、开话题的 chip 不折。
- 没有完成标记的回合不折（活还在跑）。
- 折叠胶囊文案带上数量：`已处理 1分 31秒 · 6 个步骤`，因为它现在是这一回合唯一的
  折叠，读者得知道里面有多少东西。

### 3. 两个胶囊合成一个 `RunReceiptPill`

`AssistantTurnChip` 与 `ActivityRunChip` 共用同一个胶囊：同样的 `minisGrouped`
填充、18dp 圆角、`展开`/`收起`、勾或转圈。展开后的步骤各自是独立 receipt，
不再互相收角。

### 4. 底部留白

`BOTTOM_CONTENT_GAP` 10dp → 22dp，最后一行与快捷胶囊之间留出一行的呼吸。

## 不做

- 不改 `ActivityDetail` 的三种档位的语义：`FULL` 仍逐步显示，`HIDDEN` 仍全隐。
- 不把步骤做成可点的子卡（工具详情面板是另一个任务）。
- 不动 iOS 的 `endsRun` 注释：那是 Swift 侧的文件，不在这里。

## 测试

- `TranscriptPresentationTest`（core）：叙述可见只折步骤；`HIDDEN` 保留叙述；
  只有步骤的回合合成一个 receipt；没有完成标记不折；失败/状态行不折；
  搜索命中落在折叠内的步骤时能展开。
- `TranscriptRunTest`：卡片两侧都断开 run；chip 两侧也断开。
- `TranscriptPresentationTest`（app）：`已处理 4秒 · 2 个步骤` 可见、展开后
  `read` / `bash` 出现、收起后消失。

## 验证
