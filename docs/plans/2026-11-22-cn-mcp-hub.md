# 国内 MCP 接入页

2026-11-22 · `feat/cn-mcp-hub`（基于 `origin/main` `b641b50105`）

## 背景

Plugins 的 Marketplace 来自 Composio 目录。实测（2026-11-22）Composio v3 API 对
feishu/lark/dingtalk/wecom/wechat/tencent/baidu/aliyun/gitee/yuque/amap/gaode/bilibili/
xiaohongshu/douyin/weibo/zhihu/tmall/taobao/jd 全部返回空；`composio.dev/toolkits/*` 200 探测
只命中 `lark`（且要用户自己的 Lark OAuth 应用，仅 self-hosted 模式可用）。官方目录页也无
「中国」分组。离线兜底 `CURATED` 24 项同样全是国外服务。

结果是国内用户打开 Apps 看不到任何国内服务，唯一的三个国内卡片（腾讯地图/百度地图/飞常准）
藏在「全部应用」里，点任何分类胶囊就消失（`inCategoryView` 时 `shown()` 恒 false）。

## 调研结论（2026-11-22 实测，非文档推断）

### 三条路对比

| | Composio | ModelScope 魔搭 | MCP 官方 Registry |
| --- | --- | --- | --- |
| 国内服务 | 0 | 12,944（需自己托管） | 直连 + stdio 皆有 |
| 接口性质 | 商业私有 | 未公开内部接口 | **公开标准（v0/servers）** |
| 用户令牌 | Composio key | 必须魔搭账号 | **不需要** |
| 地址有效期 | 永久 | **24 小时**（详情页原文） | 永久 |
| 国内可达 | 出境，慢 | 快 | 600–950ms，5/5 全通 |
| 维护成本 | 低 | 高（常驻刷新调度） | 低（关键词搜索 + 缓存） |

选 **官方 Registry**：唯一同时满足「公开接口 + 不要令牌 + 地址永久 + 国内可达」。

### 已排除

- **魔搭托管 URL 24h 过期**（详情页原文「有效期 24 小时有效」），不做自动刷新调度。
- **飞书/钉钉/语雀只有 stdio**：`npx -y @larksuiteoapi/lark-mcp mcp -a -s`（874★）、
  `npx -y dingtalk-mcp@latest`（29★）、`npx yuque-mcp`（269★）。现有 `McpServerEditor`
  已支持 stdio，不另造模板机制。
- **不存在的域名**（DoH 权威 NXDOMAIN，非网络问题）：`mcp.aliyun.com`、`mcp.volcengine.com`、
  `mcp.deepseek.com`、`mcp.kimi.com`、`mcp.bilibili.com`、`mcp.zhihu.com`、`mcp.juejin.cn`、
  `mcp.mi.com`、`mcp.cloud.tencent.com`。
- **mcp-cn.com**（MCP Hub 中国）：只有导航，无直连地址，`is_domestic` 全为 0。
- **官方 Registry 全量翻页不可行**：≥40,000 条，400 页耗时 586s（撞上限）。只能按关键词搜索。

## 方案

### 一页、两源

```
国内服务（胶囊）
├─ 即点即用（无 Key）      12306 火车票、pianam 日历
├─ 填 Key 即用            微博 / 知乎 / B站 / 抖音 / 视频号 / 贴吧 / 公众号发布 / 腾讯 CloudBase
├─ 已有直连（迁入本页）     高德 / 滴滴 / Gitee / 腾讯地图 / 百度地图 / 飞常准 / 智谱
└─ Registry 补充         按关键词从官方 Registry 拉到的其余国内服务
```

### 数据来源

1. **静态表** `shared/cn-mcp.ts`：已实测的 17 项，含端点、鉴权方式、Key 申请地址、
   分类。端点与鉴权是人工核对过的事实，不依赖运行时。
2. **Registry 补充**：`GET registry.modelcontextprotocol.io/v0/servers?search=<词>&limit=20`，
   20 个国内关键词并发查，24h 磁盘缓存（`DATA_DIR/cn-mcp-catalog.json`），失败回落上次缓存。
   Registry 只提供 `remotes[]` 直连项，stdio 项不出现。

### 落地即普通 MCP server

勾选后走现有 `POST /api/mcp/servers`，落成标准 `{ type: "http"|"sse", url, headers?, enabled }`：

- Key 一律存 Vault（`POST /api/vault/secrets`），config 里只留 `vault:<id>` 指针
  （query 参数用 `?key=vault:<id>`，header 用 `Authorization: Bearer vault:<id>`）。
- 新建默认 `enabled: false`，用户自己开——与 `POST /api/mcp/servers/import` 语义一致，
  不会偷偷给 bot 开权限。
- 因此自动获得：bot 授权、工具列表、健康检查、Connected 计数、`mcp.changed` 广播。

## 不做

- 不做魔搭同步（24h 过期 + 内部接口）。
- 不做 stdio 模板（现有编辑器已够）。
- 不改 `HOSTED_MCP_APPS` 里已有的三个国内卡片（避免破坏现有连接）。

## 验收

- 无 Key 服务点一下即连，工具能列出来。
- 填 Key 服务：Key 进 Vault，config 只有指针，断开时删除。
- Registry 补充区 24h 内不重复请求；网络失败时用缓存。
- 老用户不受影响（不动 `HOSTED_MCP_APPS` 已有项）。
- `pnpm typecheck` / 定向 vitest / `oxlint --deny-warnings` / `i18n:check` 全绿。
